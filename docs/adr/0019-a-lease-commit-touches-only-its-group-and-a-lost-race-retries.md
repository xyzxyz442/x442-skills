# A lease commit touches only its group, and a lost race retries

Every lease write regenerates the board's whole set of generated indexes and pushes them in one
commit, so two claims of unrelated handoffs in different groups contend on the same files. We
decided a lease commit regenerates only the files its own group needs, and that a lost push
race retries automatically instead of handing every collision to a person. This refines
ADR 0002.

## Context

- Every `claim`, `release`, `checkpoint` and `move` regenerates the roll-up `INDEX.md`, each
  `INDEX-<group>.md`, and orchestrator children tables, and stages them into the same pushed
  commit. Every write on the board therefore contends on the same files, even two claims of
  unrelated handoffs in different groups.
- A `claim` whose push is rejected rolls the lease back, fetches only to report who won, and
  tells the person to re-run it. There is no automatic retry. `release` warns and leaves the
  push to the person.
- A team with over a hundred repos in groups, with agents claiming concurrently, makes this
  routine.
- The session-start listing already reads only the local clone and only the repo's own group,
  so the listing is not the problem; the shared generated files are.

## Decision

- **A lease commit regenerates only its own group**: that group's `INDEX-<group>.md` and the
  children tables of orchestrators whose children changed. The roll-up `INDEX.md` is
  regenerated by `handoff index` or CI.
- **A lost race retries**: on a rejected push, fetch, re-check that the lease is still free (if
  another session now holds it, stop and report as today), rebuild the generated files from the
  fetched state, commit, push — up to 3 attempts. Generated files are never merged, only
  rebuilt, which is what makes the loop a correct compare-and-swap. `release` and `checkpoint`
  use the same loop before falling back to today's warning. `claim` stays strict: after the
  last attempt it refuses.

## Considered options

- **Leave it.** Rejected — every collision reaches a person, which does not scale past a
  handful of concurrent agents.
- **Stop committing generated indexes.** Rejected — the host's web view of the board loses its
  index.
- **Per-section lease refs.** Rejected — changes the lease primitive for a problem that scoping
  solves.
- **One board per group.** Rejected — ADR 0018 keeps groups inside one board precisely so
  `depends_on` keeps working across them; splitting boards breaks it.
- **Unlimited retries.** Rejected — a livelock hides a real outage.

## Consequences

- The roll-up index can lag between `index` runs. Nothing treats that as a failure: the verifier
  does not check index freshness, and `handoff index` or CI brings the roll-up up to date.
- A payload version bump.
- A harness case for two concurrent claims.
